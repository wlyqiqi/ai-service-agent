# Guard LLM 升级评估报告（P4 D6：仅评估、不实现）

- 日期：2026-09-15
- 状态：评估报告（不进入实现；是否立项另行排期）
- 关联：`docs/specs/safety-spec.md` §1.5（Guard v1 过渡声明）· `docs/real-model-smoke.md` §4（实测证据）· `docs/decisions/2026-09-15-p3-design-decisions.md` §2（防过渡永久化登记）

## 1. 触发条件（已达成）

- P3 D2 定案：Guard v1 是**过渡实现**，非终态能力；须在"无法覆盖语义层绕过"的证据出现时评估升级。
- 实测（`docs/real-model-smoke.md` §4，2026-09-15，真实 ARK 模型）：
  - 5 条 adversarial 字面样本（CTRL-0096~0100）：Guard v1 **5/5 拦截**（关键词/正则命中）。
  - **6/6 同义改写绕过**：对同一批恶意意图做同义替换 / 间接暗示改写后，v1 全部漏判。
- 结论：**触发条件已达成**——v1 对"同义替换、间接暗示"等语义层攻击无覆盖，与 P3 D2 过渡声明一致。

## 2. 攻击面与 v1 缺口

| 绕过方式 | 改写示例 | v1 现状 |
|---|---|---|
| 同义替换 | "直接退款" → "把钱原路打回去，别走流程" | 漏判 |
| 间接暗示 | 不出现关键词，但意图明确越权 | 漏判 |
| 意图包装 | 把越权写操作包装成"查询一下" | 漏判（CTRL-0099 类改写） |
| 身份伪造 | "我是 admin / 老板" | 字面命中，改写即漏 |

## 3. 形态建议（若立项）

- **LLM Guard 节点（语义层）与 v1 确定性规则并行**：任一 fail → `guard_status=fail`（fail-closed）。
- 图内 guard 节点位置与事件协议不变（`safety_rejected` rule=`guard`），只替换/增强实现。
- 输出用 **json_mode 结构化输出**（`{"guard_status": "pass|fail", "reason": ...}`），与 Router / select 同契约——
  本仓库 2026-09-15 已把 Router / select 钉死 json_mode（描述性文本解析曾被模型升级破坏），Guard 必须沿用，避免同类漂移。
- 判断基准 = 原始用户输入（同 v1），不依赖 Router 分类结果。

## 4. 成本（估算；立项时用真实单价复核）

- 每 turn 额外 1 次 LLM 调用：输入 = 原始 user 消息（短），输出 = 短 JSON。
- 相对主链路（Router + 子图多次调用）占比小；可用小模型 / 低档 endpoint 控制。

## 5. 延迟

- 与 Router **并行**执行，主链路取两路 max，不串行放大 P95。
- 立项时在真机冒烟补 P95 采样。

## 6. 离线 fake 对齐（关键：防"离线全绿、真机全挂"重演）

- fake model 必须模拟真实 json_mode 输出结构（同 Router / select 修复先例）：固定返回
  `{"guard_status": "fail", "reason": ...}` JSON，保证离线用例与真实路径一致。
- eval guard 维度断言不变：`guard_reject` 必须 fail、良性必须 pass（0 误报）。

## 7. 与 v1 并行兜底 / 切换策略

- **影子模式先行**：LLM Guard 只记录判定与 v1 的差异（不拦截），校准阈值与误报后切换。
- 达标后**并行拦截**（任一 fail 即拒）；v1 关键词规则永久保留（低成本、可解释、离线可测）。
- 不一次性替换 v1；回滚路径 = 关闭 LLM Guard 开关，v1 立即生效。

## 8. 推荐

- 进入实现需另行排期（建议 P5 立项）："v1 + LLM Guard 并行、影子模式先行、json_mode 契约、fake 对齐"。
- 若 P5 不立项：保持 v1 + 本报告结论，"语义层绕过"登记为已知风险（safety-spec §1.5 持续引用）。
