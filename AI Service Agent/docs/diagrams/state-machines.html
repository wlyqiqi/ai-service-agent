状态机管理全景 · 谁存储、谁决策、谁转移

整个方案不是"一个"状态机，而是 4 个独立、分层管理的状态机。分层原则：轻量判断留在入口层，图内进度留在 LangGraph State，业务决策留在图内，状态存储留在外置轻量服务。

THE HEADLINE

闸门在外层，决策在图内

conversation_mode 只回答"AI 能不能碰这条消息"；图内 execution_status 回答"这个 turn 走到哪一步"。两者分层但语义一致——转人工时一个切到 human、一个置 waiting_handoff。

读图

  • 每个状态机标注了存储位置与管理位置
  • 转移标签写明触发事件（interrupt / resolve / resume）
  • Handoff Record 创建与 mode 切换是同一事务
